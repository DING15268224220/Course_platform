高校课程项目协作与评审平台 V4.0 —— 需求实现说明

一、版本定位

V4.0 在 V3.1 的 Flask + SQLite + 原生 JavaScript + Electron 框架上增量完善，不改变整体技术架构、视觉系统和启动方式。V3 文件夹保持不变，V4 独立存放于 Course_platform_v4。

二、V4 新增业务功能

1. 新增教务管理员角色，支持全局课程项目查看、成绩复核、撤回发布、归档导出和审计查询。
2. 新增教师创建课程、项目保存草稿、草稿确认发布、多迭代追加及评分权重修改。
3. 入队流程改为学生申请、组长审批；增加教师或管理员带理由的成员例外调整。
4. 新增组长分配迭代任务、成员个人任务列表及待开始/进行中/已完成状态。
5. 成果提交允许团队负责人或该迭代的指定成员操作，保留版本并增加并发版本冲突校验。
6. 新增助教按迭代查收、退回修改和阶段评分；各阶段过程分自动汇总为团队过程分。
7. 新增按迭代批量识别未提交团队并发送站内催交通知。
8. 匿名互评新增完成度、创新性、文档质量三个维度及草稿功能，综合分自动取三维平均。
9. 互评分配只面向已有有效提交的团队；少于四个团队时按实际数量降级轮转。
10. 新增异常评分标准差预警，教师或助教必须填写复核结论；存在未处理预警时禁止发布成绩。
11. 保留去除最高分和最低分、缺评扣分、个人折算系数、人工扣分和 0—100 分截断规则。
12. 成绩发布生成团队和个人不可变快照，支持撤回后修正并重新发布。
13. 新增学生成绩复核申请、教师/教务管理员处理、结果通知与全过程留痕。
14. 成绩归档支持 Excel 和 PDF 两种格式，并写入文件 SHA-256 摘要和导出日志。
15. 学生可查看本人相关操作记录；教师、助教和管理员按权限查看项目日志。

三、安全、通知与可靠性

1. 连续五次登录失败后账号锁定 15 分钟。
2. 密码继续使用 PBKDF2 加盐哈希，写接口继续使用 CSRF 校验。
3. 新增 X-Content-Type-Options、X-Frame-Options 和 Referrer-Policy 安全响应头。
4. 设置 PLATFORM_HTTPS=1 时启用 Secure Cookie 和 HSTS，便于 HTTPS 部署。
5. 审计日志采用 SHA-256 前向哈希链，管理员可主动校验是否存在异常篡改。
6. 教务管理员可创建 SQLite 全量备份，备份保存在运行数据目录的 backups 子目录。
7. 登录时自动检查组队、互评和项目截止时间，在到期前 24 小时及到期后生成一次性提醒。
8. 同一提交记录支持 lock_version 乐观并发校验，发现旧版本提交时提示刷新。

四、验证结果

1. Python 后端语法检查通过。
2. JavaScript 前端语法检查通过。
3. 后端自动化测试共 24 项，结果为 24 passed。
4. 健康检查返回 version=4.0.0。
5. 教务管理员、教师、助教和学生四类账号均完成登录及 bootstrap 数据检查。
6. 1920×1080 登录页完成真实浏览器无头渲染检查。

五、部署边界

1. 大文件采用完整文件上传，尚未引入云对象存储分片协议；本地版通过 200MB 限制、文件头校验和失败不入库保证数据完整。
2. HTTPS 证书、校园统一身份认证和外部邮件网关属于部署环境能力，代码已保留安全配置入口，但需学校服务器与网关参数才能正式启用。
3. 需求中的 AI 智能体为低优先级扩展项，V4 不将其纳入核心验收闭环。
4. 百人并发指标需要在实际部署服务器上使用 JMeter 进行正式压测；本地自动化测试不等同于生产压测报告。
